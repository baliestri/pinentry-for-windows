= GPG Agent Compatibility Tests

The compatibility suite exercises Pinentry For Windows with command sequences modeled after real `gpg-agent` sessions.
It is designed to catch regressions in common GnuPG workflows without requiring UI interaction during normal test runs.

== Default Replay Suite

The always-on suite lives in `tests/PinentryForWindows.Tests/GpgAgentCompatibilityTests.cs` and runs with:

[source,powershell]
----
dotnet test PinentryForWindows.slnx
----

These tests replay sanitized Assuan command sequences through the same command handlers used by the executable.
Credential and dialog services are mocked, so the tests do not open CredUI, request Windows Hello, access hardware, or modify the user's real GnuPG configuration.

Covered replay scenarios include:

* decrypting a message with an external-cache miss
* signing a message with an external-cache hit
* generating a key with repeat-passphrase confirmation
* smart-card style descriptions with `Number:` and `Holder:` metadata
* clearing a cached passphrase with `CLEARPASSPHRASE`
* cancellation returned as the GnuPG cancelled error
* retry after a bad passphrase with `SETERROR`
* repeat-passphrase mismatch returned as the not-confirmed error

The replay suite asserts stable compatibility invariants such as cache-key construction, cache-user extraction, prompt retry behavior, and Assuan response codes.
It intentionally avoids exact full prompt wording unless that wording is part of current behavior.

== Optional Live GPG Smoke Tests

The PowerShell smoke script can run a disposable-key GPG scenario when GnuPG is installed:

[source,powershell]
----
pwsh -NoProfile -ExecutionPolicy Bypass -File tests/Test-PinentryForWindows.ps1 -IncludeGpgKeyTests
----

The script creates a temporary `GNUPGHOME`, writes a temporary `gpg-agent.conf`, generates a throwaway key, signs a message, kills the temporary `gpg-agent`, and removes the temporary home during cleanup.
It must not use or modify the user's real GnuPG home.

Interactive prompt, Windows Hello cache, dialog, and cancellation checks are opt-in:

[source,powershell]
----
pwsh -NoProfile -ExecutionPolicy Bypass -File tests/Test-PinentryForWindows.ps1 -Interactive
----

Additional switches include:

[cols="1,3", options="header"]
|===
| Switch | Behavior

| `-RequireWindowsHelloCache`
| Fails the cache-hit scenario unless `GETPIN` returns `S PASSWORD_FROM_CACHE`.

| `-IncludeDialogTests`
| Runs manual `MESSAGE` and `CONFIRM --one-button` dialog checks.

| `-IncludeCancelTests`
| Runs a manual cancellation scenario for `GETPIN`.

| `-IncludeGpgKeyTests`
| Creates a temporary `GNUPGHOME`, generates a throwaway GPG key, signs a message, then cleans up.
|===

== Safety Rules For New Compatibility Tests

New always-on tests should be replay based and non-interactive.
They should mock credential and dialog services instead of launching Windows UI.

New live GPG scenarios must:

* use a temporary `GNUPGHOME`
* generate only disposable keys
* kill the temporary `gpg-agent` during cleanup
* remove generated keys and temporary files during cleanup
* be opt-in when they require UI, Windows Hello, hardware, or installed GnuPG tools
* avoid logging passphrases or cached secret values

Hardware-dependent smart-card tests should remain manual or explicitly opt-in.
The default replay suite should cover smart-card command metadata without requiring a card reader or token.
